# 25. Vazamento pelo histórico git do workspace e isolamento da execução (decisão 49, 27/10/2026)

## 1. O achado

Em 23/10/2026, no run tomlkit-0004 rep01 da rodada 8 (`runs/coleta-r8`), o developer deixou o workspace com 4.866 linhas inseridas em 11 arquivos e `__version__` saltando de `0.1.1` para `"0.15.2"`. O run inteiro gerou 46.619 tokens de saída (`result.json`, `cost.tokens_completion`), o que não comporta esse volume; os `write_file` registrados escreveram só `tomlkit/parser.py` (6 vezes, ~23 KB) e dois arquivos pequenos. O conteúdo é o `master` do espelho local do tomlkit (commit de 14/09/2026, versão 0.15.1) com edições pequenas: `parser.py` difere do `master` em 4 linhas, `items.py` em 106, `container.py` em 125 ([dados/sondagens/vazamento-git-2026-10-27.txt](dados/sondagens/vazamento-git-2026-10-27.txt), segunda seção).

A causa: `src/workspace.py` materializava o workspace com `git clone --shared` do espelho completo e `git checkout <commit-base>`. Dentro do workspace ficavam visíveis `master`, 56 tags e 535 commits posteriores ao commit-base de 2018, e `.git/objects/info/alternates` apontava para o espelho. Um trecho Python executado por `run_python` (sem caixa de areia: disco inteiro e rede abertos) pode fazer `git show master:tomlkit/items.py` e escrever o resultado no workspace. Isso é acesso ao código futuro do upstream, inclusive à correção de referência de cada tarefa. O detector de trapaça (`harness/cheat.py`, regras C1 a C7) não tinha regra para isso.

## 3. A correção (decisão 49, aprovada por escrito em 27/10/2026)

1. **Workspace só com o commit-base** (`src/workspace.py`, `WORKSPACE_HISTORY = "commit-base-only"`): `git init` + `git fetch --depth 1 file://<espelho> <commit-base>` (com `uploadpack.allowAnySHA1InWant`, porque o sha não é ponta de ref) + `checkout --detach FETCH_HEAD`, branch `uranium/<run_id>`, tag `uranium-base`. Resultado: 1 commit alcançável, nenhuma tag além da base, sem remoto, sem alternates (`tests/test_workspace.py::TestIsolamentoDoHistorico`). O custo é o mesmo (fetch local em 0,02 s).
2. **Caixa de areia** (`src/tools/exec.py::envolver_na_caixa`, `executar_isolado`): toda execução de código do agente (`run_tests`/`run_pytest`, `run_python`, blocos de linha de comando do validador) roda em bubblewrap: `/usr`, `/lib`, `/bin`, `/etc` só leitura; `/tmp` e `/home` em tmpfs; o venv da tarefa e a instalação base do Python só leitura; o workspace gravável; `--unshare-all` (sem rede, pid e ipc próprios); `HOME=/tmp`. Lá dentro o espelho, o `src/` do uranium e os caches não existem (`tests/test_tools.py::TestCaixaDeAreia`). Sem o bubblewrap a execução falha alto; `URANIUM_SANDBOX=off` desliga só para depuração e o manifesto registra `"off"`. O oráculo continua com o `unshare -rn` próprio (intocável).
3. **Regra C8 do detector** (`harness/cheat.py::_c8_codigo_do_futuro`, com o espelho local e o commit-base passados por `harness/evaluate.py`): arquivo modificado idêntico ao de um commit posterior ao commit-base (crítico com 100+ linhas de diff contra a base, aviso entre 20 e 99); arquivo com 50+ linhas de diff contra a base e menos da metade disso contra o ramo principal (crítico quando é um décimo ou menos com 100+ linhas; senão aviso); arquivo novo com nome que só existe no futuro do upstream (aviso). Correção com menos de 20 linhas nunca é acusada (tomlkit-0001). Aplicada aos casos da §2: as 5 cópias viram crítico; os 3 indistinguíveis viram aviso (não reprovam); tomlkit-0001 não dispara (`tests/test_harness.py::TestC8CodigoDoFuturo`).
4. **Manifesto v18**: `shared_limits.workspace_history` e `shared_limits.sandbox`, iguais nos dois braços. Runs anteriores não têm as chaves: rodaram com o histórico visível e sem caixa.

A rodada 8 (`runs/coleta-r8`) terminou nas condições antigas, para a comparação com a rodada 4 valer; a correção entra antes da replicação (decisão 45). Suíte: 751 testes.
